# 步 05：定位注入点与向量锚点

## 目标

为当前 hash 建立带行号的注入点、V、几何 N 映射；为默认的两档外观切换建立最终 N、L、T / 手性映射，并用 regcheck 证明捕获前无覆写。

## 进入条件

- [ ] 步 04 已产出严格编译与关键位运算回环通过的 `<底子 fixed HLSL>`。
- [ ] 已确认它是目标材质 PS，而非描边、阴影或 prepass。
- [ ] 本步只读取和标注当前 hash；不复用别的 hash 的寄存器名或行号。

|---|---|---|---|

## 操作

1. 先从目标 draw 的 diffuse 采样结果向后追踪，确认当前版本乘上的染色常量与 cb 编号。`cb6[6]` 是 2026-09 案例，不能跳过这次确认。把现场表达式写成 `<染色常量正则>` 后搜索全部候选：

   ```powershell
   pwsh -NoProfile -Command "Select-String -LiteralPath '<底子 fixed HLSL>' -Pattern '<染色常量正则>' -Context 4,4"
   ```

   同一个 cb 可能在别处使用；只有乘到漫反射采样结果、随后进入原 sRGB / LUT / 光照 / 湿身 / 落雪链的那一行是注入锚点。记录该行号与赋值左值。确认当前染色 cb 后仍找不到这条材质链，才能把 U2 判成非材质 PS 并回步 00。
2. 列出输入签名中的 TEXCOORD1 / 2 / 3，先把 semantic 对应到本文件自己的参数名：

   ```powershell
   pwsh -NoProfile -Command "Select-String -LiteralPath '<底子 fixed HLSL>' -Pattern 'TEXCOORD1|TEXCOORD2|TEXCOORD3'"
   ```

3. 定位 V：从 `TEXCOORD1` 参数向下追踪 `dot(x,x)` → `rsqrt` → `x * rsqrt` 的归一化链。透视分支常退化为 `normalize(-TEXCOORD1.xyz)`，但必须按当前 HLSL 证明。归一化完成后立即捕获成具名 `float3`，不要等寄存器被雾或大气代码复用。
4. 定位透肉 N：取 `TEXCOORD2` 对应的世界空间几何法线并归一化。这里刻意不用 NormalMap 后的最终法线；透肉边缘权重来自几何表面朝向，才能避免法线贴图纹理把透肉打碎。
5. 对 V 与几何 N 各验证一次“最后赋值之后到捕获之前没有再写”。一条命令可检查多组：

   ```powershell
   python scripts/regcheck.py "<底子 fixed HLSL>" "<V 寄存器分量>" <V 检查起始行> <V 捕获行> "<N 寄存器分量>" <N 检查起始行> <N 捕获行>
   ```

   退出码 0 与末行 `结果:全部干净` 才能使用这些捕获点；退出码 1 表示区间内有写入，必须把捕获点前移到最后一次赋值后；输入不完整或 `--help` 返回 2 是脚本现有例外，不能改脚本来“修”帮助退出码。
6. 建立证据表。每一格都填写“semantic / 来源表达式、最后赋值行、捕获行、regcheck 结果”，不能只写寄存器名：

   | 量 | 来源 | 最后赋值行 | 捕获行 | regcheck |
   |---|---|---:|---:|---|
   | 注入点 | 当前染色常量 × diffuse 的左值 | 现场填写 | 紧跟其后 | 不适用 |
   | V | TEXCOORD1 归一化链 | 现场填写 | 现场填写 | 0 处写入 |
   | 几何 N | TEXCOORD2 归一化 | 现场填写 | 现场填写 | 0 处写入 |
7. 默认外观切换包含第 1 档高光，所以即使启动时显示第 0 档，也必须按 [variable-mapping.md](variable-mapping.md) 再定位最终 N、L、T 与切线手性：

   - 高光 N：NormalMap 采样、TBN 变换和归一化之后的出口；后面同时参与 NdotV / NdotL。
   - L：从主光 cbuffer 构造，并与主光颜色 / 强度同一分支出现。真 3D 与水平投影两种候选都记录，后续用游戏内 NdotL 探针裁决。
   - T / 手性：TEXCOORD3 的 xyz / w；T 在核心内相对 N 正交化，w 参与副切线方向。
   - 可用 `0.399999976` 附近的 NdotV / NdotL 三连快速找到候选，但锚点只负责定位，不保证寄存器尚未被覆写。
8. 对高光最终 N 与 L 重跑独立 regcheck：

   ```powershell
   python scripts/regcheck.py "<底子 fixed HLSL>" "<高光 N 寄存器分量>" <高光 N 检查起始行> <高光 N 捕获行> "<L 寄存器分量>" <L 检查起始行> <L 捕获行>
   ```

9. 在证据表中追加高光 N、L、T 与手性。T / 手性直接来自输入参数时写清 TEXCOORD3 的声明行；L 的两个候选分别保留到后续探针，不靠强度调参掩盖方向错误。

## 期望输出

本轮没有对 Yvonne HLSL 执行 regcheck。下面是脚本源码定义的 stdout 结构示例，不是真实执行结果：

```text
== r?.xyz 在 ... 行内的写入:0 处 == ← 每一个量都必须为 0
== r?.yzw 在 ... 行内的写入:0 处 ==
结果:全部干净 ← 退出码 0
```

出现覆写时结构为：

```text
== r?.xyz 在 ... 行内的写入:... 处 ==
  {line}: {assignment}
结果:有写入,捕获点或区间要重定 ← 退出码 1
```

已有 `regcheck.help.log` 记录 `python ...regcheck.py --help` 的退出码为 2；这是保持脚本行为不变的已知例外。

## 判定

| 看到什么 | 结论 | 下一步 |
|---|---|---|
| 找到唯一“当前染色常量 × diffuse”链，后续仍进入原材质流程 | 注入点成立 | 继续定位 V / N |
| 找到染色常量，但乘的不是漫反射采样 | 锚点选错 | 继续向采样与最终颜色方向追踪；不得记录为注入点 |
| V 和几何 N 的 regcheck 都是 0 处写入 | 透肉向量可安全捕获 | 继续定位默认高光档的 N/L/T |
| 任一区间有写入 | 捕获时读到的值已变化 | 把捕获移到该量最后一次赋值之后，重跑 regcheck |
| 用户明确取消整个高光切换功能 | 无需生成第 1 档 | 记录用户要求后进步 06；仅启动默认为 0 不属于此分支 |
| 最终 N、L、T / 手性都有行号证据 | 高光变量映射静态完成 | 进步 06；L 形态留给游戏内探针裁决 |
| semantic 与预期不一致 | 当前 PS 输入布局不同 | 停下按当前 main 签名重建映射，不抄档案 |

## 失败处理

| 症状 | 原因 | 修法 |
|---|---|---|
| V 到注入点前被多次写入 | 临时寄存器被复用 | 在归一化完成处立即复制到具名局部变量，再把捕获行作为区间终点 |
| 几何 N 与法线贴图 N 混淆 | 从 BRDF 出口反推时选到了最终 N | 回到 main 输入签名，从 TEXCOORD2 建立几何 N；高光 N 另列一格 |
| L 只随镜头、不随光 | 把 V、固定向量或错误 cbuffer 当成 L | 按主光方向与颜色成对出现的分支重找，保留真 3D / 水平投影两候选 |
| regcheck 返回 2 | 参数组数量错误、行号不是整数或仅调用帮助 | 按 `文件 寄存器 起始行 结束行` 四项起步，每加一组再追加三项；保留 help=2 例外 |
| 照抄同角色旧版映射后出现黑块 / 紫块 | shader hash 或寄存器分配已变 | 丢弃旧映射，对当前 `<底子 fixed HLSL>` 从 semantic 重做 |

## 产物

肤色颜色链也要记入同一证据表：光腿源 diffuse 的采样点、采样后乘数、乘数在所选状态中的取值及覆盖生命周期。B 的 `shared` 必须证明与丝袜锚点相同；不相同的固定乘数交步 06 使用 `constant`。动态 tint 或叠层不能填 `1,1,1`，先定位其真实来源及每个状态的变化条件，再完成专门映射；没有映射证据不能生成“已完成”的肤色。

| 文件 / 变量 | 放哪 | 下一步谁用 |
|---|---|---|
| 注入点左值与行号 | 当前 hash 的证据表 | 步 07 生成器参数 / 注入断言 |
| V 来源、捕获行、regcheck 结果 | 当前 hash 的证据表 | 步 07 |
| 几何 N 来源、捕获行、regcheck 结果 | 当前 hash 的证据表 | 步 07 |
| 高光最终 N / L / T / 手性证据 | 默认追加到证据表 | 步 07 与游戏内探针 |

## 本步红旗

| 念头 | 现实 |
|---|---|
| “同角色上次是 r2，这次也一样” | 只有 hash 与锚点代码都一致才可借档案，仍要对当前文件复核 |
| “法线越细越真实，所以透肉也用 NormalMap N” | 透肉用几何 N；高光才用最终材质 N |
| “锚点处看到 L 就在那里捕获” | L 寄存器可能在锚点前已被复用，必须看最后赋值与 regcheck |
| “regcheck --help 返回 2 是新 bug” | 这是现有脚本行为，用户已裁定保持不变 |
