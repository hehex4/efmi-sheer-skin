# 步 04：反编译并忠实修补底子

## 目标

把 U2 变成可严格编译、与游戏字节码关键位运算一致的 `<底子 fixed HLSL>`，尚未注入任何透肉效果。

## 进入条件

**已验证底子复用：**同一原 PS 字节码、fixed HLSL、修补工具版本及相关环境均未改变，且已有完整修补/回环通过记录时，直接沿用底子进入步 05/07，不重跑反编译和修补。调整透肉参数不触发本步；换原 PS、修改底子、更新游戏/RabbitFX 或记录不明时重新执行。

- [ ] 步 00 的 U1、U2、Q1–Q3 已全部明确。
- [ ] 步 03 的两条门控审计没有 P0 冲突；缺少正则实证时已标记为步 11 纯绿待证。
- [ ] U2 是补丁后的 `.bin` 或 `_replace.txt`，不是 `-ps.txt` 汇编。
- [ ] 输入 HLSL 保持反编译原样；尚未含 `[fix-E` 或 `[fidelity-fix` 标记。

| 占位符 | 是什么 | 从哪来 | 例子（2026-09 案例，勿照抄） |
|---|---|---|---|
| `<像素着色器 bin>` | RabbitFX 改写后的目标 PS 字节码 | 步 00 U2 | `C:\Temp\efmi-sheer\case\0123456789abcdef-ps_regex.bin` |
| `<反编译 HLSL>` | `-D` 输出；或用户给的补丁后 `_replace.txt` | 本步第 1 项 / U2 | `C:\Temp\efmi-sheer\case\source.hlsl` |
| `<游戏 msasm>` | 同一 bin 的 Microsoft 反汇编真值 | 本步第 1 项 | `C:\Temp\efmi-sheer\case\source.msasm` |

| `<底子 fixed HLSL>` | 修补脚本生成的 `.fixed.hlsl` | 本步 stdout 的 `输出:` 行 | `C:\Temp\efmi-sheer\case\fidelity\source.fixed.hlsl` |

## 操作

1. U2 为 bin 时，用同一个文件分别生成 HLSL 与 Microsoft 反汇编；U2 为 `_replace.txt` 时，直接进入第 2 项，脚本读取文件末尾内嵌汇编：

   ```powershell
   tools/cmd_Decompiler/cmd_Decompiler.exe -D "<像素着色器 bin>"
   ```

   ```powershell
   tools/cmd_Decompiler/cmd_Decompiler.exe --disassemble-ms "<像素着色器 bin>"
   ```

2. 对 bin 路线执行忠实修补。命令只读原输入，输出写入工作目录：

   ```powershell
   python scripts/fix_decompiler_defects.py "<反编译 HLSL>" --msasm "<游戏 msasm>" --out-dir "<工作目录>"
   ```

   `_replace.txt` 路线不需要 `--msasm`：

   ```powershell
   python scripts/fix_decompiler_defects.py "<反编译 HLSL>" --out-dir "<工作目录>"
   ```

3. 先看进程退出码，再读屏幕摘要：退出码 0 表示自动修补完成且严格编译 0 告警；退出码 1 表示仍有“需要手工”或严格编译失败；退出码 2 表示输入或参数错误。
4. 按 [main-ps-replacement.md 第 2 节](main-ps-replacement.md) 理解八类缺陷，每类只做忠实还原：

   | 类 | 一句话判定与修法 |
   |---|---|
   | E1 | 整数指令读取比较掩码时，布尔真值必须还原为 `0xffffffffu` / `0u`，不能把浮点比较结果直接 cast 成 uint。 |
   | E2 | `and 比较掩码, l(N)` 必须还原成 `条件 ? N : 0`，不能保留反编译器生成的两个零分支。 |
   | E3 | `texture1d + ld` 漏声明或缺对象名时，补正确 `Texture1D` 声明并用该对象的 1D `Load`。 |
   | E4 | `ld_aoffimmi` 必须按 msasm 恢复坐标维度、mip 与立即偏移，不能接受被丢成零的偏移。 |
   | E5 | `/WX` 报可能未初始化时，只给报告点名的寄存器在 `main` 开头补零初值，并核对可达路径本来都有赋值。 |
   | E6 | 整数指令或条件读取 cbuffer / 贴图原始位时使用 `asint` / `asuint`；E6c 的整数字段非零判断同样按位解释。 |
   | E7 | 整数指令造出的浮点位模式必须用 `asfloat` 存回，例如正反面乘子与按位绝对值。 |
   | E8 | 32 位位掩码、移位结果或 LCG 哈希超过 float 精确整数范围时，以位模式保存，读取处再用 `asint` / `asuint`。 |

5. 摘要出现 `需要手工 N 处` 时，逐条按它给出的 HLSL 行与对应 msasm 修正 `<底子 fixed HLSL>`；不重写无关段落，不加入透肉、高光或调参代码。
6. 摘要没有 `⚠ 编译回环有 N 项与游戏不等` 才算关键位运算回环通过。出现该行或列出“需要手工”时，运行只读候选审计：

   ```powershell
   python scripts/audit_raw_int_ops.py "<游戏 msasm>"
   ```

   审计只列 E6 / E6c / E7 候选，不能替代 HLSL 与 msasm 的逐条对照。已是 `asint` / `asuint` / `asfloat` 的位置无害；原字节码本来有 `ftou` / `ftoi` 的数值转换也无害。
7. 工作区要求逐处日志时，在第 2 项首次命令就加 `--report`，不要为同一报告重跑整套修补。已运行但未保存报告时优先记录现有 stdout；确需补缺失逐处证据才重新执行。默认不写报告文件：

   ```powershell
   python scripts/fix_decompiler_defects.py "<反编译 HLSL>" --msasm "<游戏 msasm>" --out-dir "<工作目录>" --report
   ```

8. 修补完成后再次确认 `<底子 fixed HLSL>` 里仍能找到原材质的漫反射、湿身 / 落雪路径、输出签名和 RabbitFX 高槽桥接；本步只恢复反编译忠实性。

## 判定

| 看到什么 | 结论 | 下一步 |
|---|---|---|
| 退出码 0、严格编译 0 告警、没有回环不等行 | 底子忠实门通过 | 进步 05 |
| 退出码 1 且列出“需要手工” | 自动规则不足 | 按 msasm 逐项修；修完再执行严格编译与回环核对 |
| 退出码 1 且严格编译失败 | 底子仍不能编译 | 按编译器原始错误回到对应 E1–E5；其它错误停下记录原文 |
| 退出码 2 | 输入、路径或参数错误 | 修正本步输入，禁止把它解释成 shader 缺陷 |
| 出现 `⚠ 编译回环有 N 项与游戏不等` | 重编译关键位运算与游戏不一致 | 运行 raw-int 审计并逐条对照；不得进步 05 |
| 只有提示，没有手工项，编译与回环都通过 | 提示不阻断 | 扫一眼提示后进步 05 |

## 失败处理

| 症状 | 原因 | 修法 |
|---|---|---|
| 对齐率低 | HLSL 与 msasm 不是同一 bin，或输入已被修改 | 回步 00 核对同一 hash、同一时间取得的两份文件 |
| 脚本拒绝已修文件 | 输入含修补标记 | 重新使用原始反编译 HLSL；输出仍写新工作目录 |
| E3 / E4 编译错误 | 资源类型、对象名、坐标维度或偏移丢失 | 以 msasm 的 `dcl_resource` 与 `ld` 指令为真值逐项恢复 |
| 晴天显示正常，下雨无水珠或雪地不落雪 | E6 / E6c / E7 位模式被数值转换 | 回到本步，核对天气字、灯光字段、正反面乘子；跳过本步会稳定产生这类静默缺陷 |
| 探针档编译通过，正式档失败 | 探针提前 return 后优化掉了后半段 | 以完整档的严格编译与回环为准，重新查 E1 / E2 / E6–E8 |

## 本步红旗

| 念头 | 现实 |
|---|---|
| “能编译就忠实” | E2、E6、E7、E8 都可能编译全绿而数值错误 |
| “晴天看起来正常就能跳过位模式审计” | 天气字错误只在雨雪出现，典型结果就是该部位没有水珠 / 雪 |
| “把修补和透肉一次写完” | 底子必须先独立通过忠实门，否则无法区分原缺陷与新效果 |
| “审计脚本列出的每一处都是 bug” | 它列候选；HLSL 已正确按位解释或原 asm 有 `ftou` / `ftoi` 时是无害项 |
