# 步 01：判定丝袜做法与肤色来源 👁

## 目标

用 draw、UV 岛和贴图差异三层证据，把目标归入 B 光腿贴图、C 烘焙贴图或 A 常数肤色，并确认着色器透肉的四个前提。

## 进入条件

- [ ] 步 00 已确认 U1 `<mod 文件夹>`。
- [ ] 用户要的是随视角变化的透肉，而非单纯的静态改色或亮边。
- [ ] 已知道至少一个疑似丝袜 draw 的 ini 入口；不知道时先跑本步第 1 项列候选。

## 操作

1. 先从 ini 列出每个 draw、状态条件和实际绑定贴图：

   ```powershell
   python scripts/resolve_textures.py "<mod 文件夹>" --all
   ```

   记录疑似丝袜 draw 的原 ini、段名、draw 参数、到达条件、Index / Position / Texcoord 资源与漫反射。黑丝和白丝可能是同一张图集里的两个 UV 岛，文件名不能作判据。
2. 对每个状态分支下的疑似丝袜 draw 各跑一次 UV 岛分析；多片就重复 `--piece`，每片写自己的贴图：

   ```powershell
   python scripts/stocking_preview.py --ini "<目标 ini>" --out-dir "<工作目录>" --piece "<片标签>" "<资源前缀>" "<draw 参数>" "<当前 diffuse>"
   ```

   这一步才是“独立丝袜网格”与“整块身体贴图”的判据。独立网格的岛只占小块，岛内主色是袜色，按 z 四段颜色接近；整个身体 draw 会铺出躯干、手臂与腿，覆盖更大，按 z 四段颜色差明显。

   读取输出目录的 `colour_detection.json`：`nonuniform` 为目标 UV 实际双线性采样邻域内存在颜色差异，`unknown` 为未能完整判定；两者都要求 B/C。`uniform_diffuse` 仅证明受检采样范围的 diffuse 单色，还要确认腿部范围、shader 染色和其他叠层；不能据此把整个材质直接判为单色。缩略图与中位数仅用于预览。寻址模式须从原采样器核实；未覆盖的 wrap/mirror 或动态采样不能算单色证明。
3. 先把 INI 内的相对贴图路径按 INI 所在目录转成绝对路径；`diff_texture_variants.py` 没有 `--ini`，不会替你解析这个相对关系。存在 UV 对应的光腿变体时比较两图；独立网格 UV 对应时同样可用 B：

   ```powershell
   python scripts/diff_texture_variants.py --bare "<光腿 diffuse>" --variant "<当前 diffuse>" --out "<差异图目录>"
   ```

4. 先找光腿状态的身体贴图，再对目标腿部 draw 的实际 UV 岛检查颜色，使用本步的 `stocking_preview.py` 命令分别查看丝袜与真实身体/光腿源。不能只看中位数、文件名、整张图集或几个顶点。光腿源有渐变、红晕、纹身、花纹或不同区域肤色时，优先 B 直接保留它；目标 UV 不对应才用 C 烘焙。未完整采样而不能证明单色，也必须保留逐像素来源；材质额外染色/叠层也计入判定。非单色或不确定时不得降级为 A。

   按下面条件选肤色来源：

   - B 光腿贴图（最优先）：存在真实光腿状态身体贴图，且目标 draw 的 UV 能对应到同一腿部区域，就直接作为肤色来源；尤其应保留非单一肤色和材质纹理。独立网格若 UV 已对应，也可用 B，不必重复烘焙。
   - C 烘焙肤色贴图：B 无法直接对应目标 UV 时使用。步 06 将真实身体/光腿源按三角形表面映射到目标 UV；非单色或不确定时必须完成烘焙，不能降级常数。
   - A 常数肤色：仅在目标腿部材质已被完整核实为单色、且用户知道单色腿效果弱仍决定做时可用（见 SKILL.md「开工提示 P0」的【提示·腿是单色】），必须量本角色自己的颜色并转线性。缺图、缺缓冲、距离失败或不确定均不是允许 A 的理由。
5. 对照四个前提逐项打勾：

   - 肤色与袜色有足够色差；最大通道差小于 30 sRGB 级时，透肉几乎不可见。
   - B 有光腿变体，或 C 有完整身体几何，或 A 有本角色皮肤色来源。
   - 能把袜子像素与同 PS 的身体、内衣、鞋、手套等区域分开。
   - U2 是本次新取的材质 PS，且步 03 能证明门控有人定义、没有冲突。
6. 资源同名不代表同一 draw：按实际索引切片、位置、UV 和当次贴图判断。共享 buffer 的身体与丝袜可属于不同切片；同几何配真实光腿变体也能烘焙。禁止把目标袜色贴图当身体肤色源；缺真实源时补齐后继续烘焙，不改成常数交付。
7. 最后再做目标分诊，避免把另一种效果塞进透肉流程：

   | 用户真正要的 | 路线 |
   |---|---|
   | 正对镜头透出肤色、轮廓接近袜色，效果随视角变化 | 继续本 runbook |
   | 一张固定的半透明观感 | 改 diffuse 贴图 |
   | 原材质已有透明参数，只调颜色 / 透明度 | 从帧日志取 `first_constant`，修改材质常量；见 [get-shader-bin.md](get-shader-bin.md) |
   | 沿轮廓的一圈亮边 | 使用 `efmi-fresnel-rim` |
   | 随光移动的中部亮带 | 使用 `efmi-anisotropic-highlight` |

## 判定

| 看到什么 | 结论 | 下一步 |
|---|---|---|
| UV 岛覆盖小、主色为袜色、z 四段接近 | 独立丝袜网格 | 先查 B 的 UV 对应；不对应则 C；进步 02 |
| UV 岛覆盖整个身体，或 z 四段明显属于不同部件 | 丝袜画在身体贴图上 | 继续比较贴图变体 |
| 光腿图与目标腿部 UV 对应，效果框能排除其它部件 | 光腿源可用；框外变体差异不否定 B | 优先 B，保留非单色肤色和纹理；进步 02 |
| 身体图集没有光腿变体 | 真实肤色源尚未齐 | 查身体 draw 的真实源；非单色补齐后烘焙，不能改 A |
| 丝袜盖住的区域底下没有身体几何，或身体在那里没有皮肤贴图，且本 mod 任何档位都没有完整的光腿 | 没有腿可以透出来，效果几乎为零 | 发一次 SKILL.md「开工提示 P0」的【提示·底下没有腿】，等用户决定；用户要继续，就用他另给的腿部完整来源走 B / C，没有真实来源时如实说缺什么；不得用常数肤色或袜色顶替 |
| 丝袜档底下缺身体几何，但本 mod 另有腿部完整的光腿档 | 真实肤色源存在 | 用光腿档的身体与贴图走 B 或 C；未补齐不得交付常数版 |
| 要做的每一档，肤色与袜色最大通道差都小于 30 sRGB 级 | 透肉可见度不足 | 发一次 SKILL.md「开工提示 P0」的【提示·颜色太接近】，末尾补一行实测的最大通道差，等用户决定；数字只能抄本步 `stocking_preview.py` 的 stdout，没跑出数字不得发这一段 |
| 要做的几档里只有一部分小于 30 sRGB 级 | 那几档看不出，其余档能做 | 点名告诉用户哪几档不做、各自的实测通道差，其余档继续 |
| 肤色与袜色最大通道差不小于 30 sRGB 级 | 色差够用 | 不向用户提这件事，继续；用户自己说过“颜色差不多”也以实测为准，不因目测而拒绝 |
| 真实腿部皮肤被完整核实为单色，用户还没有说过单色也要做 | 效果会很弱 | 发一次 SKILL.md「开工提示 P0」的【提示·腿是单色】，等用户决定；用户要继续就走 A |
| 用户说整条腿一个颜色，但 `colour_detection.json` 为 `nonuniform` | 目测偏差，腿上有颜色差 | 告诉用户实测有颜色差，按 B / C 正常做 |
| VP1 落在中间区间 | 视觉仍不能分类 | 停下问用户：`这片 draw 在游戏里还包含躯干或手臂吗？` |
| 四个前提全部满足 | 路线已锁定 | 进步 02 |

## 失败处理

| 症状 | 原因 | 修法 |
|---|---|---|
| `没有匹配的 draw` | 筛选过窄，或入口藏在嵌套 CommandList | 去掉筛选并保留 `--all`；进步 02 追完整调用链 |
| `UV 岛为空` | draw 参数错误、资源前缀错误或 UV 超界 | 回原 ini 核对五字段与资源段，修正本步输入后重跑 |
| `像肤色(光腿 / 皮肤嫌疑)` | 选到了光腿状态 | 回 `resolve_textures.py` 的状态条件，换成用户点名的丝袜档 |
| z 四段颜色差超过脚本阈值 | 同一片连着饰件、袜口或身体 | 用脚本建议 UV 框缩到袜子本体；这是触发 Q3 的证据，把连着的部件名带进 Q3 |
| 两张变体尺寸不同 | 不是同一图集布局 | 不能走 B；回到 C / A 判定 |
| 第 2 项误判成 C 后游戏无效果 | 烘焙把袜色复制回袜色 | 回本步重新检查 UV 岛，禁止继续调参数掩盖 |

## 本步红旗

| 念头 | 现实 |
|---|---|
| “文件名写 Stocking，所以整张都是袜子” | 一张图集常同时含丝袜、手套、内衣与皮肤 |
| “先烘一次，能跑完就是 C” | 还要确认源是真实肤色而非袜色；同几何的光腿变体可合法重采样 |
| “烘焙失败，为安全先交常数版” | 优先核对 B；B 不适用就修输入/映射后重烘，非单色不允许常数降级 |
| “独立丝袜网格下面肯定有腿” | 有的 mod 会删掉遮住的身体几何；开工提示先讲过，步 06 再用距离验证，确认没有腿就发【提示·底下没有腿】让用户决定 |
| “用户说颜色差不多，不用量了，直接回做不了” | 人眼不准；量出小于 30 级才发提示，够用就继续 |
| “脚本还没跑，先估一个通道差写上去” | 编出来的数字会误拒能做的 mod；没有 stdout 就没有结论 |
| “腿是单色，A 路线本来就允许，不用告诉用户” | 单色腿做出来只像丝袜变浅；用户还不知道就先发【提示·腿是单色】，由他决定 |
| “查到没有腿，不说了，先做出来让用户自己看” | 查到就发一次【提示·底下没有腿】；做不做由用户决定，但不能瞒着 |
| “肉色袜也能靠透肉做明显” | 肤色与袜色接近时，可变化的颜色上限接近零 |
| “亮边和中部亮带也是透肉参数” | 两者分别属于 Fresnel 与 anisotropic highlight |
