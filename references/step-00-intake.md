# 步 00：收齐输入并锁定开工边界 👁

## 目标

收齐能开始只读分诊的 U1、U2，认清着色器文件类型，并把第二轮三问与正式开工门登记清楚。

## 进入条件

- [ ] 用户明确要做随视角变化的丝袜 / 薄纱透肉，或要修现有透肉效果。
- [ ] 已读取当前工作区的 `AGENTS.md`、项目说明和用户本轮口头约束。
- [ ] 尚未修改 mod、`d3dx.ini`、ShaderFixes 或 skill 自身文件。

## 输入

| 占位符 | 是什么 | 从哪来 | 例子（2026-09 案例，勿照抄） |
|---|---|---|---|
| `<mod 文件夹>` | 含目标 ini 的 mod 根目录；U1 | 用户明确给出 | `E:\EMFI\Mods\character\yvonne\某个 mod` |
| `<目标 PS hash>` | 丝袜材质像素着色器的 16 位 hash；U2 的第一件 | **用户在 hunting 里找出来给**；AI 不从帧里自己定 | `0123456789abcdef` |
| `<像素着色器文件>` | 文件名带这个 hash 的补丁后字节码；U2 的第二件 | 用户按点名的文件名取：`<3DMigoto 根>\ShaderCache\<目标 PS hash>-ps_regex.bin`，没有时取 `ShaderFixes\<目标 PS hash>-ps.bin` | `0123456789abcdef-ps_regex.bin` |
| `<目标状态帧>` | 启用目标 mod、主控穿目标丝袜、正常绘制的一帧转储目录，注明状态；U2 的第三件 | 用户抓；只用来核对 hash、读 draw 与绑定 | `D:/3DMigoto/FrameAnalysis-本次时间` |
| `<像素着色器 bin>` | U2 为 `.bin` 时，复制到工作目录后的副本 | 从 `<像素着色器文件>` 复制 | `C:\Temp\efmi-sheer\case\0123456789abcdef-ps_regex.bin` |
| `<工作目录>` | 本案中间产物目录 | 默认 `%TEMP%\efmi-sheer\{mod 名}\`；工作区可覆盖 | `C:\Temp\efmi-sheer\case` |
| `<状态图 1>` | 用户已提供的第一张黑丝、白丝或光腿截图 / 贴图 | 用户可选提供，并注明它代表什么状态 | `black.png` |
| `<状态图 2>` | 用户已提供的第二张状态图 | 用户可选提供，并注明它代表什么状态 | `white.dds` |
| `<状态图 3>` | 用户已提供的第三张状态图 | 用户可选提供，并注明它代表什么状态 | `bare.dds` |
| `<状态拼板>` | 三种状态图的拼板输出路径 | 本步指定 | `C:\Temp\efmi-sheer\case\state-reference.png` |

## 操作

1. 第一条回复的第一段，原样复制 [SKILL.md](../SKILL.md)「开工提示 P0」里的【开工提示】，不改写、不缩短、不挪后；用户把文件给齐了、催着直接开始也照发。它只是提示：不等用户回答，做不做由用户决定，同一条回复里接着写后面的内容。袜色和肤色是否太接近不在这里讲，也不因用户一句“差不多”就劝退：照常收文件，由步 01 实测。提示段之后再应用工作区约束：若它覆盖默认的报告、备份、安装或打包位置，紧跟着写明：`按工作区规矩，本次会：……`。
2. 接着原样复制 [SKILL.md](../SKILL.md)「第一条回复的第二段」里的【需要你提供】：必须项四样，用户已经给过且有效的那几条整行删掉，其余一个字不改。下表是同一段话按项拆开的原话，供后面单独补要某一样时使用：

   | 必须项 | 向用户要的原话 |
   |---|---|
   | U1 mod 文件夹 | `请给我这个 mod 的文件夹路径，要包含 ini 的那一层。` |
   | U2-1 PS hash | `请给我丝袜那个材质像素着色器的 hash（16 位十六进制）。找法：游戏里开 hunting，用切换像素着色器的键一个个翻，翻到丝袜变成没有明暗的纯黑剪影、别的部位照常的那一个，按标记键，hash 会复制到剪贴板。` |
   | U2-2 点名的 PS 文件 | `请给我这个文件：3DMigoto 根目录下 ShaderCache 文件夹里，名字是「你的 hash-ps_regex.bin」的那个，修改时间要是这一次运行的。没有它，就给 ShaderFixes 文件夹里的「你的 hash-ps.bin」。不要给「-ps.txt」，那是汇编，用不了。` |
   | U2-3 一帧转储 | `请在启用这个 mod、主控穿着目标丝袜、画面正常（没有 hunting 的 skip）时抓一帧，把转储目录的路径给我，并注明是哪种丝袜状态。建议先抓帧，再去 hunting 找 hash，这样帧里不会带着 skip。` |

   不说“提供 ShaderCache 目录路径”，要点名到文件名。用户已给 U1 时，先只读 `<3DMigoto 根>\d3dx.ini`，把 `next_pixelshader`、`mark_pixelshader`、`analyse_frame`、`done_hunting` 的实际按键和 `cache_shaders` 的现值写进这条回复；`cache_shaders` 为 0 时告诉用户：要在启动游戏前改成 1，ShaderCache 里才会生成那个文件。读不到 d3dx.ini 就请用户自己看这几行。并顺带问一句：`你有没有黑丝、白丝、光腿三种状态的游戏截图或贴图文件？有就发，没有也不用等。`
3. **PS hash 以用户给的为准，AI 不从帧里自己定。** 帧到手后在步 02 核对：丝袜那次 draw 的材质 pass 绑定的 PS 必须等于用户给的 hash；不相等就停下，把两个值都告诉用户，请他回 hunting 再确认一次，不自己换成帧里那个。用户只给了帧或 ShaderCache 目录、没给 hash 时，按上表原话向他要 hash，不替他从帧里或目录里挑。取证细节、抓帧前检查与光腿源帧的用途见 [取证说明](get-shader-bin.md)；抓前清除 hunting skip 与调试探针，不能用 skip 代替光腿状态。

   帧目录可能只有 PS hash 或汇编，不等于拿到 U2。新取证先读配置：`deferred_ctx_immediate` 必须保留；预计要核对身体染色时同趟包含 `dump_cb`；要提取缺失身体资源时保留对应 buffers/textures。已有工作区全量配置不缩减。不同状态只在绑定、PS 或身体源需要分别证明时补帧，不能默认要求所有状态各抓一次。

4. 收到 U2 后先认文件，不靠扩展名以外的信息猜用途：

   | 文件 | 身份 | 本案处理 |
   |---|---|---|
   | `-ps_regex.bin` / `-ps.bin` | RabbitFX 改写后的字节码 | 首选；步 04 生成 `.hlsl` 和 `.msasm` |
   | `-ps_replace.txt` | HLSL 源码 | 搜到 `t70`–`t74` 或 `t60` / `t61` 是补丁后版本；只见低槽时属于补丁前版本，必须补回 RabbitFX 功能 |
   | `-ps.txt` | 汇编文本 | 只用于看指令和已套用规则，不能当 HLSL 底子；点名向用户要 `ShaderCache` 里的 `<目标 PS hash>-ps_regex.bin` |

   只拿到 `-ps.txt` 不是配置写错。常见原因只有两类：ShaderRegex 在汇编层改写后导出 asm；反编译器处理不了过大 / 过复杂的 PS 而降级为 asm。两类都改取 ShaderCache bin。
5. U2 来自 ShaderFixes 时，先复制到工作目录。原件留在 ShaderFixes 会覆盖该 hash，并丢掉 ShaderRegex 附带命令；实机前必须征得用户同意后把原件移到备份目录，保留而不删除。
6. 用户给了任意一张状态图就核对，不等待三张齐全。按收到的数量选择一条完整命令：

   ```powershell
   python scripts/dds_view.py "<状态图 1>" --out "<状态拼板>" --size 256 --cols 1
   ```

   ```powershell
   python scripts/dds_view.py "<状态图 1>" "<状态图 2>" --out "<状态拼板>" --size 256 --cols 2
   ```

   ```powershell
   python scripts/dds_view.py "<状态图 1>" "<状态图 2>" "<状态图 3>" --out "<状态拼板>" --size 256 --cols 3
   ```

7. 步 02 读出状态分支与 draw 后，发第二轮问题，一条消息问完。Q1、Q2 必问；Q3 只在查到同一次 draw 里连着别的部件时才问，没触发就不出现，并视为已答：

   - Q1：`这个像素着色器是不是只画丝袜？hunting 里 skip 它时，除了丝袜还有没有别的部位也变成纯黑剪影？回答“只有丝袜”或“还有别的”就行，不用列全。`
   - Q2：`丝袜用哪个键切？一共几档、每档是什么？切换是否连着别的身体部件？要做哪一档或哪几档？` 变量和值由 AI 从 ini 预填。
   - 范围告知（是告知，不是提问）：`透肉范围我按丝袜本体来做（见标注图）；同一个像素着色器画的其它部件不动。`
   - Q3（条件题，查到连带部件才发）：`这次 draw 除了丝袜本体，还连着【这里填查到的部件，例如吊带、蕾丝袜口】（见标注图）。这些要不要一起透？默认不透。`

   透肉范围默认 = 丝袜本体：独立网格取该片 UV 岛并按脚本建议框收到袜子本体；丝袜画在身体贴图上时取丝袜图与光腿图的差异区。范围由 AI 自己定，不向用户提“哪些区域要透”这种开放题。触发 Q3 的证据只有一种：步 01 / 步 02 的脚本或岛图显示同一次 draw 里连着丝袜本体以外的部件。

   **Q1 的回答只当“是 / 否”信号。** 这一问只为确认这个 PS 是不是只画丝袜。用户说“还有上衣和手套”时，默认他没有说全，不把这份清单当成完整范围，也不追问让他列全。这个 PS 实际还画了什么，由 AI 在步 02 用帧里 `--ps` 的 draw 清单自己确认；用户答“只有丝袜”而清单里这个 PS 还画着别的 draw 时，以帧为准，并把查到的告诉用户。

   合格回答范例：`还有别的；三档，只做第 2 档丝袜，第 1 / 3 档是网格袜和裸腿。`
8. 把下面两条精确命令登记给步 04。只有步 02 发出的第二轮问题全部答清后才执行；本步不提前反编译。U2 是 `_replace.txt` 时，步 04 直接修补：

   ```powershell
   tools/cmd_Decompiler/cmd_Decompiler.exe -D "<像素着色器 bin>"
   ```

   ```powershell
   tools/cmd_Decompiler/cmd_Decompiler.exe --disassemble-ms "<像素着色器 bin>"
   ```

9. 把“反编译 HLSL 必须存在现场确认的染色常量 × 漫反射采样链”登记成步 04 的首个内容门。`cb6[6]` 只是 2026-09 案例，换版本先从漫反射采样向后追踪当前染色常量；确认 cb 编号没有变化后仍找不到材质链，才能判为描边 / 阴影 / 非材质 PS，并请用户回 hunting 重新确认 hash。
10. AI 自己决定效果参数、染色常量处理、RabbitFX 版本、丝袜状态初判与肤色来源；其中状态只作 Q2 预填，最终以用户答复为准；透肉范围默认丝袜本体，由 AI 定。PS hash 不在此列：它由用户给，AI 只核对。默认只做主控 LOD0。用户明确要队友透肉时，把队友 PS 作为 U2′ / U3：队友位 hunting 选同一 hash 时丝袜也应变纯黑剪影；否则另取队友 PS。
11. 全程遵守原交互规则：

   1. 第一条回复 = 【开工提示】原文在最前，后面只列用户下一步要给的具体文件。
   2. 只读核对静默完成；只有用户必须处理的问题才进入清单。
   3. U1、U2、三问未齐时不正式开工；为取得 U2 修改 `d3dx.ini` 是唯一取证例外，先备份、说明改动，取完还原。
   4. 允许只读 mod、ini、贴图和门控，也允许只读工具写预览 PNG / JSON 到工作目录；三问前禁止反编译、生成替换 HLSL、改 ini 或打包。
   5. mod 外部缺失的根目录、光腿图或皮肤图直接点名询问；用户明确让搜索后才搜索。
   6. 路径、hash、行号、cb、槽位、门控值、状态变量和按键都必须来自现场证据。
   7. 三种状态图只问一次，不等待；收到后用 VP3 对表。
   8. 默认只在下载目录留下 zip，在临时目录留下可删中间产物；工作区另有报告、备份、安装与打包规则时由工作区覆盖。
   9. 每个检验执行一次；失败后才进入对应排障分支。

## 期望输出

本步没有可伪造的固定业务 stdout。已有 `cmd_Decompiler.exe --help` 实跑证明 `-D` 与 `--disassemble-ms` 是有效入口；对业务文件的输出必须在现场生成。

以下只是消息结构示例，不是真实执行结果：

```text
【开工提示】透肉是把丝袜底下那条腿的皮肤透出来，做之前请留意两点，要不要做由你决定：

② 腿上的皮肤要有颜色变化。膝盖、脚踝这些位置和周围皮肤没有明显颜色差、整条腿一个颜色的话，做出来只像丝袜变浅了，看不出透的是腿。
查法：在游戏里切到不穿丝袜的档位；没有这个档位，就在 Blender 里把丝袜网格隐藏。你觉得不值得做，告诉我一声就停；想做就照下面准备文件。

【需要你提供】
① mod 文件夹路径，要包含 ini 的那一层。
② 丝袜那个材质像素着色器的 hash（16 位十六进制）。找法：游戏里开 hunting，用切换像素着色器的键一个个翻，翻到丝袜变成没有明暗的纯黑剪影、别的部位照常的那一个，按标记键，hash 会复制到剪贴板。这个 hash 要你来找，我不替你从帧里猜。
③ 这个文件：3DMigoto 根目录下 ShaderCache 文件夹里，名字是「你的 hash-ps_regex.bin」的那个，修改时间要是这一次运行的。没有它，就给 ShaderFixes 文件夹里的「你的 hash-ps.bin」。不要给「-ps.txt」，那是汇编，用不了。
④ 启用这个 mod、主控穿着目标丝袜、画面正常时抓的一帧转储目录，并注明是哪种丝袜状态。建议先抓帧，再去 hunting 找 hash，这样帧里不会带着 skip。
可选：黑丝 / 白丝 / 光腿三种状态图，有就给，没有继续。
四样到手后：我用帧核对你给的 hash，只读定位，再问第二轮问题；答清才开始反编译。 ← 开工门
```

## 判定

| 看到什么 | 结论 | 下一步 |
|---|---|---|
| 用户看过开工提示后说不做了 | 用户决定不做 | 停工 |
| 用户没回应开工提示，或说腿是空的 / 整条腿一个颜色但仍然要做 | 做不做由用户决定 | 照常继续；提示只发一次，不追问、不重发、不劝阻 |
| U1 或 U2 缺失 | 输入未齐 | 停下，发送本步对应的具体文件问句 |
| 用户没给 PS hash，只给了帧或 ShaderCache 目录 | U2-1 缺失 | 按本步原话向用户要 hash；不从帧里或目录里替他挑 |
| 用户给的 hash 与帧里丝袜 draw 的材质 PS 不一致 | 两者有一个不对 | 整条回复只发 SKILL.md 的【hash 对不上】并附两个值；不说哪个正确，不提议改用帧里那个，不自己换 |
| 只有 `-ps.txt` | 不是可直接注入的 HLSL | 点名向用户要 `<目标 PS hash>-ps_regex.bin`；不重复要求已提供的帧 |
| `_replace.txt` 只见低槽 | 可能是 RabbitFX 补丁前源码 | 核对补丁状态；优先取同次缓存，确需手工合并时说明缺项 |
| U1、U2 类型明确 | 只读分诊输入已齐 | 进步 01；正式施工仍等步 02 的第二轮问题答清 |
| 步 02 后三问有漏项、含糊或与 ini 冲突 | 用户边界未确认 | 只重问不清楚的原问题 |
| 步 04 按当前版本确认染色 cb 编号后仍找不到“染色常量 × 漫反射”链 | U2 不是目标材质 PS | 停下告诉用户，请他回 hunting 重新确认 hash 并按新 hash 重取点名的文件；不自己换一个 PS |

## 失败处理

| 症状 | 原因 | 修法 |
|---|---|---|
| 标记多次仍只有 `-ps.txt` | ShaderRegex 汇编层导出，或反编译失败 | 停止重复标记，升到 ShaderCache 路线 |
| ShaderCache 没有 `_regex.bin` | 该 PS 未被正则改写，或 ShaderFixes 残留覆盖 | 先备份并移走同 hash 残留，完全重启后再取；仍无则用补丁后的 `_replace.txt` |
| VP3 与 ini 初判不一致 | 状态标签或 draw 选错 | 以用户图为准，回步 02 重跑定位 |
| 用户要求队友也透，但同 hash skip 不影响队友丝袜 | LOD1 使用另一份 PS | 点名索取队友位 U2′ / U3 |
| 工作区要求报告、备份或装机 | 本 skill 默认值被项目规则覆盖 | 第一条回复写明覆盖项，后续把产物送到项目指定位置 |
