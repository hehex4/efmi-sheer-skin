# 在反编译 PS 里定位 N / L / V / T,以及按 hash 归档的已验证映射

高光核心只吃六个量。它们**每份 PS 都要重新定位**,能跨案复用的只有「同一个 shader hash」
的映射(hash 相同 = 二进制相同 = 寄存器分配相同)。按角色复用是错误 C。

| 需要的量 | 在当前 PS 里找什么 | 必须给出的证据 |
|---|---|---|
| `V` 视线 | 相机到表面方向,通常从 `TEXCOORD1` 算出并归一化 | 后面参与 `dot(·, N)` 的视角项 |
| `N` 最终法线 | 法线贴图 / 空间变换都做完之后的那个寄存器 | 后面参与 `NdotL`、`NdotV`;**赋值行到捕获行之间无覆写** |
| `L` 主光方向 | 从主光 cbuffer 构造的方向,与主光颜色成对出现 | 与 `NdotL`、主光强度同一分支 |
| `T` 切线 | 顶点输入的世界切线,先相对 N 正交化 | 与 N 同一空间;TBN 重建段里能看到 |
| 切线符号 | 切线的 `w` | 同上,`cross(...) * v4.w` |
| `originalColor` | `main` 末尾写 `SV_Target0.rgb` 的地方 | **所有分支**都写完之后再读 |

## 1. EFMI 签名约定 —— 起点,不是答案

反汇编实锤的引擎约定:

```hlsl
float4 v1 : TEXCOORD0   // UV
float4 v2 : TEXCOORD1   // 相机相对坐标  → V = normalize(cb1[4].w * (v2 + C) - v2),透视时退化成 normalize(-v2)
float4 v3 : TEXCOORD2   // 世界法线(几何法线,不是最终法线)
float4 v4 : TEXCOORD3   // 世界切线 xyz + w = 手性
uint   vN : SV_IsFrontFace
```

⚠ **v 编号会漂**。材质 ID 在一份 PS 里是 `TEXCOORD6`,在 Typhoeus 的丝袜 PS 里是
`TEXCOORD8`(多出 TEXCOORD6/7 两项)。所以约定只告诉你**去哪儿找**,每一条都要用这份 PS
自己的 `main` 签名和代码复核。

**L 不在 interpolant 里** —— 这是这条路线必须替换主 PS、不能 overlay 的根本原因。

## 2. 定位方法:认锚点模式,不认寄存器名

### V

在着色器很早的位置找 `v2` 参与的归一化链:

```hlsl
r1.xyz = v2.xyz + r0.xyz;
r1.xyz = cb1[4].www * r1.xyz + -v2.xyz;
r1.w   = dot(r1.xyz, r1.xyz);  r1.w = rsqrt(r1.w);
r2.xyz = r1.xyz * r1.www;          // ← V
```

⚠ 这个寄存器**后面会被复用**(Typhoeus 案里 `r2` 到末尾已经变成雾 / 大气项)。
在归一化完成处立即复制进具名变量,不要到插入点再现取。

### N

找法线贴图分支的出口:采样 NormalMap(EFMI 是 2 通道打包,`.xyw`)→ TBN 变换 → 归一化,
出口寄存器就是 N。证据是它后面同时参与 `dot(V, N)` 和 `dot(L, N)`。
用脚本核一遍**从赋值行到使用行之间没有再写它**。

### L —— 唯一需要实机裁决的一格

主平行光的 cbuffer 布局是标准的:`cb4[0]` 方向、`cb4[3]` 颜色(Typhoeus 实测)。构造段长这样:

```hlsl
r17.xyz = cb4[0].xyz + cb1[118].xyz;
r17.xyz = cb1[108].www * r17.xyz + -cb4[0].xyz;    // 真 3D 主光方向,未归一化
r17.w   = 6.10351562e-05;
r3.w    = dot(r17.xzw, r17.xzw);  r3.w = rsqrt(r3.w);
r20.xyz = r17.xwz * r3.www;                        // 把 y 压成 ~0 再归一化 = 水平投影
```

紧接着 `r21.xyz = -cb4[3].xyz + cb1[112].xyz; … r22 = r21 * r3.www` 是主光**颜色 × 强度**,
方向与颜色成对出现是它确实是主光的佐证。

**同一个主光有两个形态**:真 3D 未归一化的(引擎主漫反射 `dot(N, r17)` 用它,后接
`*0.5+0.5` 半兰伯特 → ramp,典型卡通主光路径)和压平的(参与下面的锚点三连)。哪个当 L
交给 Gate 2 的 NdotL 探针裁决,**不许靠调强度掩盖**(Typhoeus 案裁决结果:真 3D 形态)。

### 最好用的定位标志:锚点三连

两个不同 hash 的材质 PS 里都出现了同一组指令,连魔数都一样:

```hlsl
rA.w  = dot(V, N);                                  // NdotV
rB.yz = float2(1, 0.399999976) + -abs(rA.ww);
rC.w  = dot(L, N);                                  // NdotL
```

`0.399999976` 直接 grep 就能跳到这里;三行里同时出现 V、N、L 三个寄存器。

**锚点只是定位标志,不一定是捕获点。** 每个量要在**它最后一次赋值之后立即**捕获进具名
局部变量;捕获行离赋值行有距离的(比如在锚点处一并捕获),用 `scripts/regcheck.py` 证明
「赋值行 → 捕获行」之间没有再写它。捕获进局部变量之后,寄存器后面怎么改都不影响:

```powershell
python <skill>\scripts\regcheck.py "<转储.txt>" r17.xyz 1133 1137 r12.yzw 1104 1310 r2.xyz 142 1310
# 三段都应报 0 处写入;把 r17 的区间放宽到 1316 就会看到 1247/1249/1252 的改写 —— 这就是不能在锚点处捕获它的证据
```

两个形态的 L 干净区间**不一样**:压平形态到锚点还是干净的(之后 `.y` 马上被改);
真 3D 形态在锚点**之前**就可能被顶层代码改写成别的东西(Typhoeus 案 `r17.xyz` 在
1247 / 1249 / 1252 被无条件重算,到 1310 早已不是主光)。所以真 3D 的 L 要在构造完成处
立即捕获,不能等到锚点:

```hlsl
// 紧跟主光构造段(Typhoeus 案 1136 之后)
float3 _anisoL = <真 3D L 寄存器>;
// N / V 在各自最后赋值之后(常可放在锚点前后)
float3 _anisoN = <N 寄存器>;
float3 _anisoV = <V 寄存器>;
```

档案里写的捕获点也要用 `regcheck.py` 复核一遍再照做。

### T 与手性

TBN 重建段:`cross(v3, v4) * v4.w` 再 `+ nx * v4.xyz + nz * v3.xyz`。T = `v4.xyz`,符号 = `v4.w`。
交给核心函数前会自动相对 N 正交化。

**纤维 / 腿的方向是 T 还是 B,可以先从顶点数据预判**,不必等 Gate 3:从 mod 的 vb 读 pos + uv,
算每个三角形的 `dP/du`、`dP/dv`,与该切片包围盒主轴(腿轴)做点积取绝对值。Typhoeus 丝袜实测
`|dP/dv · 腿轴| = 0.71`、`|dP/du · 腿轴| = 0.33` ⇒ 沿腿的是 UV-v = **B 轴**,与核心函数默认
`αB > αT`(沿 B 拉长)一致。别的 mod UV 展开方向可能相反,反了就交换 `ANISO_*_ALPHA_T / _B`。

### originalColor 与插入点

`main` 末尾通常是 if/else **两个分支都写 `o0.xyz`**(受光分支 / 直出分支)。插入点在
**if/else 闭合之后、`o1` 写出之前**,这样两个分支统一生效,`o0.w`(alpha)、`o1`(MRT1)、
`discard` / `clip`、`SV_IsFrontFace` 分支全部不动:

```hlsl
  } else {
    o0.xyz = r1.xyz;
  }
  o0.xyz = ApplyAnisoHighlight(o0.xyz, _anisoN, _anisoL, _anisoV, v4.xyz, v4.w);   // ← 这里
  o1.z = 1;
  return;
```

不要在法线尚未完成、贴图尚未采样、或最终颜色之后又被原代码覆盖的位置插入。

### 空间一致性

EFMI 的 N / V / T 都在世界空间,L 从 cbuffer 构造出来也是世界空间。如果某一项不在同一空间,
先修空间再算半程向量;空间错误不能靠调强度解决,表现是亮带位置怪、随镜头乱跑。

## 4. 映射错误的典型表现

| 现象 | 多半是 |
|---|---|
| 紫色、黑块、游动条纹 | 寄存器被后续代码覆写后才读,或照抄了别的 hash |
| 亮带只在轮廓边缘 | L 取错(取成了 V 的函数)或根本没用 H |
| 亮带不随光动、只随镜头动 | L 是固定值或来自错误的 cbuffer 项 |
| 整片均匀发亮 | NdotL / NdotH 路径失效,或权重过早 saturate 到 1 |
| 亮带方向和纤维方向垂直 | T / B 弄反,或手性符号没乘 |
| 整片乌黑 | transmission、原色变量、alpha 分支;不是强度 |
