# 实机验收:四道门,按顺序过,一道都不跳

**编译通过 ≠ 效果正确;静态全绿 ≠ 变量正确。** 每一道门只回答一个问题,
不通过就停在那一道修,**不要跳到调参数**。

探针开关是替换 PS 里**粘入的核心段开头**那行 `#define ANISO_DEBUG_MODE`。改完存盘、游戏里按
**F10** 即时重载(CustomShader 的 hlsl 即时重编译,不涉及 ShaderCache,不用重启)。
⚠ F10 是 3DMigoto 的 `reload_fixes` 键,**不要把它绑成 mod 的开关键**;想要游戏内热键调参,
用 `[` `]` 这类 OEM 键,并先 grep 全 Mods 确认没人占用,IniParams 槽位同理。
第一次安装、或 ini 改动后,完全退出游戏再启动一次,别只靠热重载判断。

| ANISO_DEBUG_MODE | 显示 | 回答的问题 |
|---|---|---|
| 1 | 整片纯绿 | Gate 1:替换 PS 被执行了吗?打中的是目标几何吗? |
| 2 | NdotL 灰度 | Gate 2:N 与 L 对吗?迎光白、背光黑 |
| 3 | NdotV 灰度 | Gate 2:V 对吗?正对镜头白、边缘黑 |
| 4 | 切线 RGB | Gate 2:T 对吗?应沿纤维方向平滑变化 |
| 5 | NdotH 灰度 | Gate 2:亮斑随光**和**镜头一起动吗? |
| 6 | 夸张橙色亮带 | Gate 3:位置和移动对吗?(不看好不好看) |
| 0 | 正式效果 | Gate 4 |

---

## Gate 1 — 通路命中(必过,不可跳,即使复用了已验证档案)

`ANISO_DEBUG_MODE 1`,进游戏看目标部件。

- **绿了** → 接线层(入口替换、CommandList、`ps ==` 门控、CustomShader、draw 切片)全部
  无误;之后任何问题都只可能在着色器里。
- **没绿,只查这五样,禁止调 GGX / Fresnel 参数**:
  1. 屏幕角落有没有 3DMigoto 红字(着色器编译失败会直接显示)
  2. 跨 mod `filter_index` 冲突 —— 重跑 `audit_filter_index.py` 扫真实 Mods 根
  3. CommandList 是否真的被调用:原 draw 行是不是真换成了 `run =`
  4. 当前显示的是 LOD0 还是 LOD1 —— 只接了 LOD0 就去队友位看
  5. `ps = .\res\xxx.hlsl` 路径是否存在(相对 ini 所在目录)
- **别的部件也绿了** → draw 参数锁错了,回探测表核对完整五字段。

---

## Gate 2 — 变量语义(唯一允许跳过的情况见末尾)

按 2 → 3 → 4 → 5 的顺序,每一档只看自己那件事:

| 档 | 正常 | 不正常 = |
|---|---|---|
| 2 NdotL | 朝光的一面白、背光黑,**转动光照 / 角色时明暗面跟着转** | 不随光动 = L 是常量或取错项;整片白/黑 = N 或 L 空间错 |
| 3 NdotV | 正对镜头白、轮廓黑,转镜头时渐变跟着转 | 不随镜头动 = V 取错 |
| 4 切线 | 颜色沿纤维方向平滑变化 | 整片纯色 = T 取错或没归一化;补丁状 = 手性符号错 |
| 5 NdotH | 一个亮斑,**光动它动、镜头动它也动** | 只随其一 = H 的 L 或 V 有一个错 |

**L 的两个形态在这一档裁决**:压平版(y≈0 归一化)和真 3D 版只差 y 分量,
`NdotL` 灰度在角色抬头 / 低头、光从高处打下来时会分出差别。把用户看到的现象写在回复里,
选和引擎自己漫反射一致的那个;**AI 不能看编译输出就宣称变量正确,必须以用户的观察为准。**

## Gate 3 — 夸张亮带,只看位置和移动

`ANISO_DEBUG_MODE 6`:合成权重(core ∪ halo)×4,染成橙色。依次观察:

1. 迎光面:亮带在受光方向附近出现
2. 转动镜头:亮带**移动**,不粘在屏幕边缘
3. 转动角色或改变光照:亮带跟着走
4. 亮带方向沿纤维方向拉长(丝袜是沿腿的方向)

**只在边缘 = 仍然是 Fresnel 或 L 取错,不是强度太低**;方向垂直 = T/B 反了,交换
`ANISO_*_ALPHA_T / _B`(可以先按 variable-mapping.md「T 与手性」一节用顶点数据预判)。
这一档不通过就回 Gate 2,不进 Gate 4。

## Gate 4 — 正式材质

`ANISO_DEBUG_MODE 0`,从默认参数起调。**每次只动一组**:

| 想要 | 改哪个 | 方向 |
|---|---|---|
| 中央亮带更窄 / 更宽 | `ANISO_CORE_ALPHA_T` | 降 / 升 |
| 亮带沿纤维更长 | `ANISO_CORE_ALPHA_B` | 升 |
| 两侧渐变更宽 | `ANISO_HALO_ALPHA_T` | 一次不超过 +0.05 |
| 两侧渐变更弱 | `ANISO_HALO_GAIN` 或 `ANISO_HALO_WEIGHT_*` | 降 |
| 中央亮带更弱 | `ANISO_CORE_GAIN` 或 `ANISO_CORE_WEIGHT_*` | 降 |
| 浅棕更暗 | `ANISO_LIGHT_TINT` | 三分量同比例降 |
| 整体丝袜太黑 | `ANISO_TRANSMIT_FRONT / GRAZE` | 小幅升 |
| 出现白色曝光 | 不许改成加法;确认最终仍是 `lerp` | — |

亮带**位置**不对时不许靠强度掩盖,回 Gate 2 核对映射。

## 故障对照

| 现象 | 优先查 |
|---|---|
| **Gate 1/2 全过,一切到 Gate 3 或 Gate 4 就卡死 / 花屏 / 崩** | **不是性能,也不是接线。**探针档 1..5 提前 return,编译器把后面整段(常含光源循环)优化掉,bin 能从 75 KB 缩到 18 KB ⇒ 那些代码**只在完整档 0/6 执行**。回 main-ps-replacement.md 第 2 节查 **E2**(`and <cmp>, l(N)` 退化成 `? 0.000000 : 0`,编译得过但值是错的,常被拿去当数组索引)与 E1 |
| 完全没变化 | 同 hash 跨 mod `filter_index` 冲突 → 目标 draw / LOD / CommandList 是否命中 |
| 探针能变色,正式效果不明显 | 映射或强度,不是接线 |
| 只有轮廓边缘发亮 | 只做了 `1 - NdotV`;缺 `H = L + V` 的镜面项 |
| 高光不随光移动 | L 不是当前主光方向,或误用固定方向 |
| 紫色、黑块、游动条纹 | 贴图 / 常量槽错、法线空间错、寄存器已被覆写、越界读取 |
| 整片均匀发亮 | NdotL / NdotH 路径失效,或权重过早 saturate 到 1 |
| 亮带变白 | 白色加法,或输出仍在 HDR 范围累加 |
| LOD 切换后效果消失 | 漏了 LOD1 / 跨 IB 入口 |
| 替换后 mod 贴图 / 改色 / 法线失效 | mod 是 RabbitFX 注入高槽而替换 PS 只采低槽;核对 t70/t71/t72 与反射 |
| 阴影 / 深度 pass 出紫色黑块 | CommandList 的 `else` 没回退原 draw,或 ps 门控没生效 |

## 收工前的完整回归

- 队友位(LOD1)与主控位表现一致
- 阴影、深度、描边 pass 无紫色 / 黑块 / 条纹
- mod 原有的菜单、服装切换状态、跨 IB 身体、大招 / 特殊形态不受影响
- 帧率无可感知变化
- `ANISO_DEBUG_MODE` 改回 0
- 这份 hash 的映射与 L 最终形态就在生成命令的 `--aniso-n / --aniso-l` 里(写在装机 hlsl 的头部),不另建档案、不改 skill 里的文件

## 唯一允许跳过 Gate 2 的情况

精确 shader hash、锚点代码、资源布局都与档案里**已实机验证**的配置完全一致,并且回复里
说明了引用的是哪份档案。即使如此,Gate 1 仍不能跳。
