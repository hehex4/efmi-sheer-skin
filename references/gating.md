# 门控:为什么要两半,以及不用分类器的退路

## 为什么门控是 `vs == 202 && ps == 1718.1`

同一片网格每帧会被画好几次:阴影、深度预处理、上色(材质)、描边。替换 PS 只能换在**上色**那一次。

- `ps == 1718.1` 是共享 RabbitFX 贴在一整族材质着色器上的标签,**描边那一次也带着它**。只写这一半,替换 PS 会被套到描边 pass 上,
  读到那一步根本没绑的常量缓冲 —— 实例是显卡卡死(2026-09-09 庄方仪案)。
- `vs == 202` 是 CrossIB 分类器贴在「上色那一步的顶点着色器」上的标签,正好把上色和描边分开。
- ini 里没有别的信号能分开这两次:两次用同一份索引、同样的 draw 参数,`index_count` 之类一样;RabbitFX 的 PS 标签也一样。

所以两半缺一不可。任何一半没人定义,整条条件永远为假,替换走 `else` 回退原 draw,**游戏里一切照旧、没有任何报错**。

## 首选:用全局分类器

见 [步 03「门控」](step-03-gate.md):先审计,确实没有才从本包 `assets/` 装一份,全局只留一份。

## 退路:按编号给材质 VS 贴 202(不推荐)

分类器实在装不了时,可以只给**这一次 draw 用的材质顶点着色器**贴同一个标签,放在这个 mod 自己的 ini 里:

```ini
[ShaderOverrideSheerMaterialVS_<短 hash>]
hash = <材质 pass 的 VS hash,16 位,从帧转储 log 里查>
filter_index = 202
allow_duplicate_hash = overrule
```

LOD1 如果用的是另一个 VS,再加一段。这就是 efmi-crossib-builder 里旧的「hash-starter」写法。

必须遵守:

- **值只能是 202。** 一个着色器只能带一个 filter_index,而材质 VS 是所有角色共用的(皮肤族、布料族各一份)。
  写成别的值会把这个 VS 从 202 改掉,所有靠 202 的 CrossIB mod 当场失效。写 202,日后用户装了分类器,两边说的也是同一个数。
- **不能改贴 PS**:PS 身上已经有 RabbitFX 的 1718.x,再贴会把 RabbitFX 的门控弄坏。

代价(所以不推荐):

- VS hash 随游戏更新会变,每次更新都要重查、重写;分类器按特征匹配,不怕换 hash。
- 本项目已经把这类按 hash 的旁路文件迁到了分类器(skill efmi-migrate-crossib-rules 就是干这个的);再加回去,等于给后人留一份要迁移的旧东西。
